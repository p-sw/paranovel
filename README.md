# ParaNovel

ParaNovel은 AI가 장기 연재형 한국 웹소설을 집필할 수 있도록 Canon, 회차 기억, 현재·이전·대기 아크, 현재 장면, 혼합 검색 기억과 사용자가 승인한 개선점을 한데 묶어 제공하는 단일 사용자용 집필 환경입니다. React 편집기와 NestJS API를 하나의 Docker 이미지로 빌드하며 데이터는 SQLite에 저장합니다.

## 주요 흐름

- 프로젝트를 만들 때 로그라인과 장르 태그를 먼저 받고, AI 인터뷰가 어울리는 소설 제목을 추천합니다. 추천 제목은 그대로 쓰거나 자유롭게 고칠 수 있습니다.
- 제목 다음에는 목표 완결 회차를 선택적으로 입력합니다. 비워 두면 AI가 작품 규모에 맞는 완결 회차를 정하고, 어느 경우든 1화부터 결말까지 빈틈없이 이어지는 전체 아크를 작성합니다.
- AI 인터뷰는 세계의 시대·공간과 규칙, 인물의 욕망·과거·관계, 능력의 비용과 한계, 적대 세력과 장기 갈등을 구체화합니다. 인터뷰가 끝나면 작품 정보, 초기 Canon과 전체 아크를 한 화면에서 검토·수정한 뒤에만 프로젝트에 적용합니다.
- 인터뷰의 이전 질문과 답변을 다시 확인할 수 있습니다. 이전 답을 수정하면 이후 질문을 다시 진행하며, 선택형 질문의 직접 입력은 ‘기타’를 선택한 경우에만 사용할 수 있습니다.
- 프로젝트별 아크는 5~20화 단위로 관리합니다. 집필에 적용 중인 `ACTIVE` 현재 아크와 이미 지나간 `COMPLETE` 이전 아크는 보호되며, `PLANNED` 대기 아크는 실제 전개나 사용자 요청에 맞춰 편집·교체할 수 있습니다. 끝나기 전에 교체한 현재 아크는 읽기 전용 `ARCHIVED` 기록으로 남습니다.
- ‘인물 외형’ 정사에 머리카락·눈동자·피부색·체형·의상·장신구 등 상세한 시각 정보를 저장합니다. 소설 본문에서 외형 설명을 생략해도 AI는 확정된 외형 정사를 참고합니다.
- 프로젝트의 ‘AI 채팅’에서 설정·아크·개선점을 질문하거나 생성·수정·삭제를 요청할 수 있습니다. 대화는 저장되며 변경안의 적용 버튼을 눌러야 반영됩니다. 채팅은 기존 회차를 읽어 분석할 수 있고, 회차 본문 작성은 회차 화면에서 진행합니다. 개선점 변경은 현재 프로젝트에 한정됩니다.
- AI 채팅에서 확정된 인물 외형·장소와 장면 설명을 지정해 이미지 생성용 태그를 요청할 수 있습니다. 채팅 AI가 내부 태그 생성 도구를 호출하고 전용 Luna 작업이 단부루 스타일의 영문 단어 태그를 반환하며, 실제 이미지를 생성하거나 정사를 변경하지 않습니다.
- ‘새 채팅’으로 대화 주제를 나눌 수 있습니다. ‘채팅 기록’에는 채팅방 제목, 마지막 메시지 미리보기와 최근 대화 시간이 표시되며, 이전 방을 열어 대화와 변경 제안을 이어서 확인할 수 있습니다. 새 방에는 다른 방의 대화가 포함되지 않고 작품 설정은 함께 참고합니다. 기존 대화는 업데이트 시 프로젝트별 이전 채팅방으로 보존됩니다.
- 새 회차는 ‘이번 회차에 원하는 것’만 선택 입력합니다. 비워 둔 채 다음으로 넘어가도 AI가 제목과 전개 방향을 자동으로 만듭니다. 이 단계부터 ‘미완성’ 회차로 저장되며, 목록에서 클릭하면 다이얼로그를 다시 열어 이어서 다듬을 수 있습니다.
- 제목·전개 방향 다이얼로그에서 ‘AI 회차 작성’을 누르면 해당 회차의 편집기로 이동해 본문을 스트리밍하고 일관성을 검사합니다. 생성이 중단되거나 검사에 실패해도 받은 본문은 검토가 필요한 원고로 보존됩니다. ‘빈 회차로 시작’은 같은 회차의 편집기를 열어 직접 작성합니다.
- ‘새 회차’나 ‘첫 회차 만들기’를 누르면 검토 중인 정사를 확인합니다. 후보가 있으면 경고창에서 ‘정사 검토하기’로 이동하거나 ‘계속 만들기’를 선택할 수 있습니다. 정사 탭의 ‘검토 중만 보기’는 분류·검색과 함께 사용할 수 있습니다.
- 회차 목록의 ‘수정’에서 카드를 드래그하면 순서에 따라 회차 번호가 바뀝니다. 빠진 번호는 ‘빈 회차’ 카드로 표시되며, 수정 중 이동하거나 바로 삭제할 수 있습니다. ‘완료’에서 저장하고 ‘취소’로 되돌립니다. 새 회차는 빈 카드를 포함한 마지막 자리 다음 번호로 생성되며, 아무 카드도 없으면 1화부터 시작합니다.
- 생성된 제목과 전개 방향에 ‘개선 요청’을 입력하고 ‘개선’을 누르면 요청한 부분을 다듬습니다. 직접 수정한 내용과 이전 개선 결과를 기준으로 반복해서 개선한 뒤 초안을 생성할 수 있습니다.
- 생성 결과는 Canon과 기억을 기준으로 설정·시간대·장소의 정합성을 검토한 뒤 편집기에 원문 그대로 반환됩니다. 표시된 문제는 사용자가 항목별 ‘자동 수정’을 선택할 때만 수정됩니다.
- 순수 텍스트 편집기의 커서 위치에서 AI 이어쓰기를 요청할 수 있습니다.
- 회차 에디터 상단의 ‘편집 AI’에서 집필 모델과 대화하며 장면을 쓰거나 원고를 수정합니다. 선택문이 있으면 그 부분만 수정하고, 선택문이 없으면 AI가 요청에 맞는 범위를 직접 찾습니다. 이어쓰기는 커서 위치(선택한 적이 없으면 원고 끝)에 삽입문을 제안합니다. 모든 수정안은 채팅창의 카드에서 수정 전·후를 비교하고 ‘수락하고 적용’을 눌러야 본문에 반영됩니다. 대화는 회차별로 저장되며, 수락 전 원고가 바뀌면 현재 원고를 기준으로 다시 요청해야 합니다.
- 선택한 원문을 사용자가 고친 뒤 두 텍스트의 차이에서 개선점 후보를 추출합니다. 편집기에서 만든 개선점은 현재 프로젝트 범위가 기본입니다.
- ‘두 원고 비교’는 두 방식으로 사용할 수 있습니다. 공통 방향·브리프를 입력하면 AI 초안을 먼저 확인한 뒤 수정 원고를 입력합니다. 원고만 입력하는 경우에는 전·후 원고를 각각 직접 입력합니다. 두 방식 모두 전 원고 대비 후 원고의 개선점을 추출하며, 개선점은 전역 범위가 기본입니다.
- 승인된 전역 개선점과 현재 프로젝트 개선점은 이후 관련 AI 집필 요청에 함께 반영됩니다.

## 기억과 정합성

AI 요청의 문맥은 다음 우선순위로 조립됩니다.

1. 작업별 프롬프트와 공통 집필 규칙
2. 승인된 개선점
3. Canon
4. 현재 아크
5. 현재 장면
6. 최근 회차 기억과 열린 떡밥
7. 벡터·키워드 혼합 검색 결과
8. 현재 사용자 입력

Canon은 사용자가 확정한 사실만 포함합니다. 회차에서 새로 발견된 사실은 후보로 추출할 수 있지만 자동으로 Canon에 편입하지 않습니다. 검색은 프로젝트별로 격리되며, OpenRouter 임베딩을 사용할 수 없으면 SQLite 키워드 검색으로 자동 폴백합니다.

AI 초안과 이어쓰기의 일관성 검사는 설정·시간대·장소의 사실 오류만 보고합니다. 시점·시제·회상 등 서술 기법이나 문체·구성은 검사 대상이 아닙니다. 생성 후 검사는 차단 문제가 있어도 본문을 자동으로 수정하지 않으며, 스트리밍된 초안의 줄바꿈과 공백까지 그대로 유지합니다. 사용자가 문제별 수정 방향을 확인하고 ‘자동 수정’을 누른 경우에만 해당 항목을 고칩니다.

## 기술 구성

- 프런트엔드: React (`apps/web`)
- 백엔드: NestJS (`apps/api`)
- 데이터베이스: SQLite
- AI 게이트웨이: OpenRouter
- 외부 레퍼런스 검색: Tavily Search
- 기본 집필 모델: `google/gemini-3.8-flash`
- 개선점 추출 모델: `openai/gpt-5.6-luna`
- 통합 채팅 모델: `openai/gpt-5.6-luna`
- 이미지 태그 생성 모델: `openai/gpt-5.6-luna`
- 기본 임베딩 모델: `openai/text-embedding-3-small`, 1536차원

## 로컬 실행

Node.js 22 이상과 npm이 필요합니다.

```bash
cp .env.example .env
npm ci
npm run dev
```

개발 서버는 React UI를 `http://localhost:5173`, NestJS API를 `http://localhost:3000`에서 실행합니다. 프로덕션 빌드와 Docker 이미지는 UI와 API를 모두 `http://localhost:3000`에서 제공합니다. `OPENROUTER_API_KEY` 없이도 프로젝트·회차·설정 CRUD와 키워드 검색은 사용할 수 있습니다. 이 경우 AI 생성 및 임베딩 요청은 `503 Service Unavailable`을 반환합니다.

프로덕션 빌드를 확인하려면 다음을 실행합니다.

```bash
npm run build
npm test
```

빌드 계약은 React 결과를 `apps/web/dist`에 만들고 NestJS 결과를 `apps/api/dist/main.js`에 만드는 것입니다. NestJS가 빌드된 React 자산도 정적으로 제공하므로 운영 환경에는 별도 웹 서버가 필요하지 않습니다.

## 프롬프트 관리

고정된 자연어 지시문은 코드에 두지 않고 모두 [`prompts`](./prompts)에 저장합니다. 레지스트리는 공통 프롬프트 `novelist-core`와 `memory-contract`를 작업 프롬프트와 함께 불러옵니다.

각 파일에는 다음 YAML front matter가 필요합니다.

```yaml
---
id: episode-draft
version: 1
task: episode_draft
responseMode: text
requiredVariables:
  - canon
---
```

- `responseMode`는 `text`, `json`, `tool` 중 하나입니다.
- 본문에는 `## System`과 `## User` 구역이 모두 있어야 합니다.
- 템플릿 변수는 `{{snake_case}}` 형식을 사용하고 `requiredVariables`에 등록합니다.
- 프롬프트는 파일 수정 시각을 기준으로 런타임에 다시 읽힙니다. 필수 파일, 구역 또는 변수가 없으면 해당 AI 요청이 명확한 구성 오류로 실패합니다.
- `json` 작업의 구체적인 응답 형태와 `tool` 작업의 도구 스키마는 코드에서 타입 안전하게 제공하며, 자연어 의미와 행동 규칙은 프롬프트 파일에 둡니다.

Docker에서 프롬프트를 이미지 재빌드 없이 조정하려면 Compose 서비스에 읽기 전용 바인드 마운트를 추가할 수 있습니다.

```yaml
volumes:
  - ./prompts:/app/prompts:ro
  - paranovel_data:/data
```

## 웹 레퍼런스 검색

`.env`에 `TAVILY_API_KEY`를 설정하고 API 서버를 재시작하면 프로젝트 청사진, 세계관, 아크, 회차 방향, 초안·이어쓰기, 비교용 초안 생성에 Tavily를 사용할 수 있습니다. Docker Compose도 같은 변수를 컨테이너에 전달합니다. 집필 모델은 OpenRouter의 function calling을 지원해야 합니다.

최종 생성 전에 LLM이 `tavily_search` 도구로 레퍼런스 필요성을 판단하고, 서버가 [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)를 호출한 결과를 LLM에 돌려줍니다. 검색이 불필요하면 곧바로 준비 단계를 마칩니다. 키를 설정한 경우에는 검색하지 않아도 이 판단을 위한 LLM 호출이 한 번 추가됩니다. 검색 결과는 제목·URL·최대 2,000자의 발췌와 함께 최종 작업에 전달하며, 최종 본문은 기존 방식으로 스트리밍합니다. 검색 판단과 최종 출력의 토큰 사용량은 같은 AI 실행 기록에 합산합니다.

사용 조건, JSON 인자와 예시, 출처 확인, Canon 우선순위, 검색 실패 시 처리는 [`reference-tools.md`](./prompts/reference-tools.md)에, 조사 단계의 종료 조건은 [`reference-research.md`](./prompts/reference-research.md)에 있습니다. 검색 인자는 `query`(1~400자), `search_depth`(`basic` 또는 `advanced`), `max_results`(1~5)입니다. 요청당 최대 3회 검색하며, 검색 한 번의 제한 시간은 15초입니다. API 키는 서버에서만 사용하고 검색어만 Tavily에 전달합니다.

키가 없으면 기존 생성 흐름을 사용합니다. 빈 결과, 검색 오류, 한도 도달 시에는 받은 자료로 작업을 계속하되 검색 성공이나 확인하지 못한 출처를 꾸미지 않도록 지시합니다. 프로젝트 인터뷰, 기억·장면·개선점 추출, 연속성 검토와 최소 수정에는 외부 검색을 추가하지 않습니다. 웹 자료는 참고용이며 작품의 확정 Canon이나 회차 기억으로 자동 편입되지 않습니다.

## 인물 외형

‘정사·설정’의 ‘인물 외형’ 분류를 사용해 기존 인물 설정과 별도로 외형을 자세히 기록합니다. 같은 인물 이름으로 두 분류를 함께 저장할 수 있습니다. AI 기획·설정 후보 생성·채팅에서도 이 분류를 사용할 수 있으며, AI의 제안은 기존과 같이 사용자가 승인한 뒤 정사로 사용됩니다. 상세한 외형 정사를 소설 본문에 매번 나열할 필요는 없습니다.

## Docker 단일 이미지

```bash
cp .env.example .env
docker compose up --build -d
```

Compose는 React 정적 자산과 NestJS API가 포함된 단일 컨테이너를 실행하고, named volume `paranovel_data`에 `/data/paranovel.sqlite`를 보존합니다. 컨테이너를 삭제해도 volume을 삭제하지 않는 한 소설 데이터는 남습니다. 운영 데이터는 volume 전체를 정기적으로 백업하세요.

AI 채팅 오류는 다음 명령으로 서버 로그를 확인할 수 있습니다.

```bash
docker compose logs -f --tail=100 paranovel
```

`chat_send_started`와 `chat_send_completed`는 시작·완료 기록입니다. `chat_send_failed`에는 실패 단계(`stage`), 프로젝트·메시지 ID, AI 실행 ID(`runId`), 모델, 소요 시간과 원래 예외가 남습니다. AI 호출 전 오류는 `runId`가 `null`입니다. `proposal_validate`는 변경 제안 검증 실패, `proposal_persist`는 제안 저장 실패, `message_persist`는 답변 저장 실패입니다. 제안 오류의 `proposal.index`는 0부터 시작하며, `error.issues`의 필드 경로와 조건 또는 `error.cause`에서 구체적인 원인을 확인합니다.

`chat_failure_status_write_failed`가 함께 나오면 실패 상태의 DB 저장도 실패한 것이므로, 같은 메시지 ID의 앞선 `chat_send_failed`를 먼저 확인하세요. AI 실행 자체의 오류는 `ai_run_failed`, 그 실행의 실패 상태 저장 오류는 `ai_run_failure_status_write_failed`로 기록하며 같은 `runId`로 연결합니다. 공통 HTTP 5xx 오류는 `http_request_failed`로 기록합니다. 로그에는 대화·AI 답변 전문, 인증 헤더와 SQL 매개변수를 기록하지 않습니다.

레지스트리에 로그인한 뒤 한 번의 명령으로 이미지를 빌드하고 푸시할 수 있습니다.

```bash
./scripts/build-and-push.sh ghcr.io/OWNER/paranovel:1.0.0
```

기본 플랫폼은 `linux/amd64,linux/arm64`입니다. 단일 플랫폼이나 다른 조합이 필요하면 `PLATFORMS`를 지정합니다.

```bash
PLATFORMS=linux/amd64 ./scripts/build-and-push.sh ghcr.io/OWNER/paranovel:1.0.0
```

스크립트는 `docker buildx`와 대상 레지스트리에 대한 사전 로그인을 요구합니다.

## 데이터 보호

- `.env`와 SQLite 파일은 이미지 빌드 컨텍스트에서 제외됩니다.
- API 키를 프런트엔드 코드나 브라우저 저장소에 넣지 마세요. OpenRouter·Tavily 호출은 NestJS 서버에서만 수행합니다.
- SQLite 파일을 복사해 백업할 때는 쓰기를 중단하거나 SQLite의 안전한 백업 절차를 사용해 WAL 파일과의 불일치를 피하세요.
